# NEXUS Architecture

Date: 2026-08-14

## Purpose

NEXUS is an operational intelligence web app for inventory, requests, approvals,
fulfillment, reporting, audit, admin/RBAC, and a database-backed Copilot.

The assessment brief asks for a runnable app, tests, a real AI-assisted change
loop, and documentation that clearly explains what works. This document covers
the implemented system architecture.

## Components

- Frontend: React + Vite + TypeScript in `Fronted/`.
- Backend API: FastAPI in `Backend/app/`.
- Database: Supabase PostgreSQL, managed through SQLAlchemy and Alembic.
- Auth: Supabase Auth JWTs validated by the backend.
- Tests: `pytest` backend tests; frontend TypeScript/build verification.

## Data Flow

1. Browser loads the React app.
2. User signs in through Supabase Auth.
3. Frontend stores the Supabase access token in the auth store.
4. API client sends `Authorization: Bearer <token>` to FastAPI.
5. FastAPI validates the JWT and loads the matching NEXUS user.
6. Routes call service-layer functions.
7. Services read/write PostgreSQL through SQLAlchemy sessions.
8. Serializers return frontend-shaped JSON.

## Backend Structure

- `app/api/routes/`: thin FastAPI route handlers.
- `app/services/`: business logic and deterministic calculations.
- `app/models/`: SQLAlchemy models.
- `app/database/`: session, health checks, app seed, Auth seed.
- `migrations/`: Alembic schema migration.
- `tests/`: unit and configuration tests.

## Frontend Structure

- `src/pages/`: screen-level app routes.
- `src/api/`: typed backend API clients.
- `src/store/`: persisted UI/auth/operations state.
- `src/components/`: reusable layout and UI controls.

Route pages are lazy-loaded and Vite manual chunks split heavier vendor code
for faster first load.

## Key Design Choices

- PostgreSQL only. SQLite is rejected by configuration validation.
- Backend services calculate dashboard, insight, and decision metrics from DB
  records instead of frontend constants.
- Copilot is deterministic and DB-backed; it persists conversations/messages.
- Report downloads are generated by the backend as PDF, CSV, or XLSX content.
- Demo Auth accounts are provisioned through a controlled script that repairs
  Supabase Auth token defaults without printing secrets.

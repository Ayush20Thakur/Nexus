1. Assessment Overview
What this is. A one-week, build-it-yourself assessment. You will design and build a small
working web application, then use AI tooling to generate and run its test automation, make
a feature change through that AI loop, and produce a professional documentation set —
finishing with a short recorded demo.
Why it looks like this. We are not testing whether you can write code from memory. We
are testing whether you can direct AI to build, test and correct real software. Using AI is
expected and encouraged. What we assess is the quality of the system you end up with,
the judgement behind your choices, and your ability to explain and demonstrate it live.
What we are looking for. Engineering judgement under an open brief, the ability to close a
build → test → fix loop rather than just generate code, care about security and correctness,
clear written and spoken communication, and honesty about what did and did not work.
A well-reasoned partial solution with an honest account of where it broke will score higher
than a polished-looking submission that does not actually run. Do not fake results.
2. What You Will Build
Stage 1 — Pick a scenario and build a web app
Choose your own scenario. Anything real enough to have rules and edge cases — a library
issue/return system, a canteen ordering system, a leave-approval workflow, a small
inventory or invoicing tool. Pick one specific functionality within it and build that properly
rather than building five features shallowly.
Any technology stack you like. It must run, and someone else must be able to start it from
your repository using your README.
Stage 2 — AI-generated test automation
Use an AI tool to generate the test scripts for your chosen functionality, then actually run
them and capture the results. Cover the normal path, the edge cases and the invalid inputs.
Important: a test that always passes proves nothing. Your suite must be able to
fail. Show us at least one run where you deliberately break the application and
the tests catch it (a red run).

Stage 3 — The AI change loop (the core of this assessment)
This is the part we care about most. Give the AI a new feature request for your application,
and have it:
1. implement the change in your codebase,
2. run your existing test suite against it,
3. detect what broke, and
4. correct itself until the suite passes again.
Then capture the evidence: prompts given, what the AI changed, which tests failed, what it
did about it, and how many attempts it took. Where the loop failed or you had to step in
manually, say so.
Stage 4 — Documentation set
Produce, with AI assistance:
• Architecture document — components, data flow, technology choices and why.
• Design document — data model, key flows, API or interface design, error handling.
• User guide — how a non-technical person uses the feature you built.

4. Ground Rules
• AI tools are allowed and expected — Claude, ChatGPT, Copilot, Cursor, or any
coding agent.
• Name your tools. List every AI tool you used and what you used it for.

• Your work must run. We will start your application and run your tests from your
repository.
• Be prepared to defend it. Shortlisted candidates will be asked to walk through their
code and explain design decisions live. Submitting work you cannot explain is the
fastest way to be ruled out.
• Individual submission. Discuss approaches with peers if you like; the build must
be yours.
Suggested starting points (not prescriptive): web — React, Next.js, Django, Flask, Spring
Boot, Node/Express. Testing — Playwright, Selenium, Cypress, pytest, JUnit, Jest. CI —
GitHub Actions. Free tiers of every one of these are sufficient; do not spend money on this
assessment.

6. Timeline and Submission
• Time allowed: one week from the date this brief is issued.
• Submit: all six deliverables above, in one folder or repository, to the address on
your invite.
• Questions: ask early rather than guessing — clarifying an ambiguous brief is part of
engineering.
